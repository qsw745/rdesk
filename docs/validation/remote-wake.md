## 审查与修复

一次独立只读终审：3 项 Important、0 项 Critical、无遗留 Minor。已修复并验证：

1. 网卡介质使用官方数值 14，替换错误的字符串判断；真实格式测试先失败后通过。
2. 助手停用保留身份与电脑绑定，重新启用轮换凭据；旧令牌与迟到停止不能停止新凭据。手机也支持更换绑定助手、删除失效助手。
3. 页面展示助手最近在线、领取、发送回执、电脑上线时间与助手错误码；离线后保留最近时间用于排障，不把旧时间当作在线证据。

另修复：地址读取失败不锁死按钮；通知授权等待期间退出后不会启动助手；服务端已注销成功时，本机停止异常不能留住已删除账号；Windows 心跳停止时立即失效异步世代。

干净检出暴露原有协议模块入口被 `.gitignore` 错误忽略；现将仅包含 OUT_DIR include 的 `crates/rdesk_common/src/protos/mod.rs` 纳入版本控制，生成的协议文件仍不提交。

## 决策与边界

- 沿用用户要求的 master/当前工作区，逐文件保留原有修改；代价是需额外用干净快照验证提交。
- 计划任务标题规范为 Task N 供执行工具解析；仅改变标识，无产品行为影响。
- 服务端任务 1/2 合并为可独立编译的提交；其余跨平台集成合并验收，便于一起回滚。
- 高熵随机设备令牌用 SHA-256 摘要，人类密码算法不变；若未来令牌降低熵，须重评摘要方案。
- 长轮询每 100 ms 检查一次队列，最长 5 秒；代价是最多约 100 ms 额外领取等待。
- 原生凭据附账号归属，恢复同账号界面时不误停已手动开启的助手；切换身份必须停止。
- 30 秒冷却从请求创建算起；活动请求另行去重，可能比终态起算更早允许重试。
- 部分 Provider/UI 测试在实现后补充，不声称全部测试先行；关键故障与审查发现均有失败复现。
- APK 代替无可用实机时的安装交付；不保证任何未测硬件、电源状态或安卓厂商后台策略。
- 已签发许可最多 2 秒，不能隔网撤回；回执丢失时保守不重发。Windows 登录前没有应用心跳，不能把“未确认上线”当成物理开机失败。

## 部署流程（后续执行记录另附）

部署目标与服务保持项目现状：`101.37.21.147`、`rdesk-server`、`/var/lib/rdesk-server/data/rdesk-users.json`、本机 HTTP 21116、公网 HTTPS 入口。获得部署确认后：

1. 记录线上旧版本与运行二进制，备份用户及 auth-session 数据；新程序同样使用原用户文件并新增可选 wake 字段。
2. 仅在本地构建经过验证的 master 快照，目标 Linux x86_64；在本地 Linux 容器验证成品后上传并比对 SHA-256，保留旧 `/usr/local/bin/rdesk-server` 备份。禁止在服务器、GitHub Actions 或其他云端 CI 构建。
3. 停服务取得一致的数据备份，再替换二进制并启动服务。检查 systemd、`http://127.0.0.1:21116/health` 与公网 HTTPS `/health`；未登录 `/api/wake/targets` 在本机和公网均应返回 401，而不是 404。多业务域名必须在 HTTPS 反代中显式转发 `/api/wake/` 到 RDesk，不能让其落入其他业务的 `/api/` 路由。
4. 在专用测试账号上用真实安卓与 Windows 配置、执行端到端验证；发布隐私/支持/下载说明后分别公开回读。GitHub Pages Support URL 需独立更新，修改 deploy/support.html 不会自动发布该网站。
5. 失败时恢复旧二进制和匹配的数据备份再重启。旧版本写用户文件会丢弃未知 wake 字段，不将二进制降级与保留新配置混为一谈。回滚前保存故障版本数据，避免覆盖升级后的正常用户操作。
