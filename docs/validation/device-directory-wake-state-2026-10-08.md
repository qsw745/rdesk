# 2026-10-08 设备重复与开机状态修复

## 现场与根因

用户确认远程开机已使 Windows 从关机状态实际启动，但 iPhone 列表仍有「正在开机」，并出现同名设备。

只读账号数据确认两类重复：Mac/手机的当前账号设备与来源未记录的旧连接历史混排；同一 Windows 网卡有不同设备码的新旧开机目标。未知来源和仅同名的设备无法直接认定为同一网络身份。

`WakeProvider` 原先仅在开机页可见时安排状态轮询。设备列表的定时刷新在详情路由覆盖后停下，详情页自身没有轮询，导致从详情页触发的活动请求停留在旧阶段。另外，刷新等待所有目标历史及本机助手状态成功后才发布，个别旧记录读取失败会挡住已成功取得的在线状态。

## 2.3.4（27）改动

- 主设备列表、桌面侧栏及账号设备计数只包含账号设备、收藏和开机目标。纯历史放入默认收起的「最近连接」，可以展开或搜索访问，原记录保留。
- 当前账号/服务器内，有效且相同的单播 MAC 目标合为一个展示组。优先当前账号在线设备码或在线目标，再按最近心跳、助手在线与稳定 ID 选择操作配置；保留所有真实服务端配置。非法、全零、组播 MAC 不跨目标合并，不按设备名合并。
- 已证实旧设备码的收藏、搜索和详情地址随展示组保留，取消收藏清除同服务器对应旧键；未知来源、其他服务器保持独立。官方旧 HTTP 来源仅窄映射 `qisw.top` 的 80/21116 端口到 HTTPS。
- 活动开机请求在应用前台持续轮询，无需进入开机页；后台停止，恢复前台立即刷新，销毁时移除生命周期观察者。最新目标先发布，局部历史/助手读取失败继续保留真实错误。
- 列表、详情及开机页共用组内请求状态。当前账号或任一同组目标在线时优先显示在线；旧活动请求不会让已在线组持续轮询。账号/服务器切换的 generation 守卫继续生效，配置确认框也冻结身份代次。
