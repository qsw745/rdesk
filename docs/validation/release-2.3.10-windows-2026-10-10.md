# Windows 2.3.10 发布记录（2026-10-10）

## 内容

源码：提交 `875ef58`（版本 2.3.10+33）；配套服务端 `ca89a93`，记录见 `server-deploy-2026-10-10.md` 的第二、三次部署。

- 文件传输：在桌面端远控界面把文件拖到远程画面上，或在文件管理页点上传，文件保存到被控电脑的「下载」文件夹。经中继单个文件最多 50 MB，局域网直连最多 2 GB。被控端收到后托盘提示。接收时先写 `.part` 临时名，完成后才改成最终名字；不覆盖已有文件；文件名只取末段并换掉 Windows 设备名。
- 远程重启、关机：只对 Windows 被控端提供，控制端二次确认，被控端 10 秒后执行。提示按被控端的应答给出，旧版本不认识该指令时如实说明没有执行。
- 观看模式入口：设备页可直接以仅观看方式连接。仅观看时键盘、鼠标、剪贴板写入、拖文件、文件管理上传、重启关机都不发送。
- 画面：Windows 采集上限由 1920 提到 2560，2K 屏幕不再缩小。
- 界面字体：Windows 上加载系统的微软雅黑作为界面字体，「置」这类笔画多的字不再糊。
- 桌面端远控界面补上实体键盘转发、鼠标滚轮滚动对方页面（对安卓被控端换成手指滑动方向）、拖动路径。

## 更正

2.3.8 的发布说明写了「对方可以直接用键盘打字和使用快捷键」。当时键盘转发只接在手机版的远控界面上，Mac 和 Windows 的桌面端远控界面没有接，说明与实际不符。本版接上并加了回归测试（`desktop_viewer_layout_test.dart` 实际发送按键并核对送出的内容）。公开的 Mac 仍是 2.3.5，Mac 控制端要用到这些功能需要 2.3.10，目前只在开发机上本地安装。

## 审查与修正

发布前做了一次安全审查和一次客户端代码审查，发现并修正：

- 中转上传在认证前读入请求体（见服务端记录第三次部署）。
- 仅观看时文件管理页仍能上传；取消上传只改了界面状态，请求还在发。
- 被控端经中继接收文件时占住指令通道，传输期间点击和按键全部排队；保存失败有几种情况不回报，对方要等到超时。
- 重启/关机先提示「已发送」再发送，不看结果。
- 滚轮方向对安卓被控端相反。
- `NUL.tar.gz` 这类名字没有被识别为设备名；文件名按字符数截短，汉字会超过 255 字节上限。
- 拖入多个文件时，前一个文件的失败提示立刻被下一个「正在发送」盖掉。
- 关机程序按名字启动，会先在应用自己的目录里找；界面字体加载只兜住了一部分异常。

没有采纳的意见：局域网上传不限并发数和累计大小（已通过认证的对方本来就能完全操作这台电脑）；同一文件连续拖两次会发两遍（按用户操作执行）。

- 终端和端口映射没有做，等认证加固完成后再做。远程目录浏览和从被控端下载文件对桌面被控端仍不可用。
