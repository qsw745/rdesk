# RDesk 2.2.0 跨平台改版验证

日期：2026-09-20。发行来源：独立干净工作树；主工作区未提交的按需录屏和审核修改不混入发行。所有编译、测试、打包均在本机、本地 Windows VM 或本地容器完成。

## 已实现

- Windows 使用 IP Helper 原生接口枚举物理有线网卡，区分检测失败、断线和未检测到；提供脱敏诊断。PowerShell 检测明确编码、时限、输出上限，并清理进程树。
- 电脑采用侧栏导航，手机采用底栏；设备、协助、开机、设置、账号按平台能力呈现。Windows 使用微软雅黑等系统字体、提高字号与对比度；设置分为常规、安全、网络、关于。
- Windows 显示五分钟二维码和手动配对码；新版 iPhone/Android 在「设备 → 扫码添加」确认，继续完成「助手 → BIOS → 测试」。二维码不能指定其他服务器，也不包含长期凭据。
- 同账号授权、领取幂等、安全存储、草稿恢复、配对过期、解绑、账号续登和服务器切换均有对应处理。手机与 Windows 必须使用同一账号和服务器。
- iPhone 是开机控制端；家中安卓手机仍需长期连接家庭 Wi-Fi、供电并允许后台运行。Windows 当前仍不支持作为远控被控端。

## 审查修复

1. 候选令牌已保存但未领取的会话过期后，只有成功查询并确认目标不存在才清理候选并允许生成新码；查询失败仍保留凭据。
2. 心跳验证前不显示配对成功；失效旧配置提供联网核实、明确确认后重新配对入口。
3. 同账号 token 更新会重建配对请求作用域，恢复本机候选记录。
4. 账号设备快照保留实际请求服务器；切换立即失效，旧请求延迟返回不能覆盖新身份；请求的凭据与端点固定。
5. 超时、输出超限、销毁统一进入幂等、可等待的进程树终止逻辑。Windows VM 中实际生成长时间运行子进程并验证其退出。

## 本次实施决定与代价

1. 使用独立工作树发行，保留原有脏修改；代价是合并时必须逐段核对重叠文件。
2. 物理网卡和唤醒另行实测；若硬件不兼容，自动测试通过仍无法保证开机。
3. 保留现有进程调用接口，在内部编码 PowerShell；必须持续验证参数和输出边界。
4. 保留 powercfg 子进程，用 taskkill /T 清理整树；增加 Windows 专属验收需求，该验收已通过。
5. 收藏以服务器来源加设备 ID 区分并保留分组入口；所有调用方必须保留来源。
6. 增加固定版本 package_info_plus 读取实际版本；需要各平台原生重建。
7. 复用设置控件、移除重复入口；原生视觉效果仍需设备确认。
8. 沿用既有登录/生物识别机制；退出尽力取消配对，离线时以五分钟 TTL 限制，不能保证立即服务端撤销。
9. 安全存储抽象复用原 Windows 凭据键，测试写入失败和丢失响应；需持续维护迁移兼容。
10. 先确定 2.2.0+17 再构建；本地编号不代表已核对或提交 App Store 新构建。
11. 手机安装安排在 API 升级后；硬件/相机/隔夜验收仍需独立证据。
12. 当前 Xcode 27 拒绝低于 iOS 15 的构建目标，仅本地命令覆盖为 15；源码兼容声明未提高，但本次本地包不能运行在 iOS 13/14，正式上架前需另行决定。
13. 一次整分支审查安排在生产部署前；后续发行元数据与部署由主代理验证，未再委派审查。
14. 按项目既有授权提交并推送 master，不重复询问集成方式；保留原有未提交工作，不自动上传 App Store。
15. 审查未判断物理硬件、原有脏修改和未来发布结果；这些结论只由各自实际证据支持，未覆盖项目明确标注。
