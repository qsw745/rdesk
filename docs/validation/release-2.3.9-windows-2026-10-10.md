# Windows 2.3.9 发布记录（2026-10-10）

## 内容

源码：提交 `db50502`（版本 2.3.9+32）。

- 被控感知：桌面端在每个页面顶部显示「本机被控中」、持续时长、对方设备数与名称、「断开所有远控」。对方名称只来自对方自己上报的信息（局域网认证或中继的信任请求）；没有时显示「有设备正在访问此电脑」，不编造。「断开所有远控」沿用托盘的做法：清空受信查看端、更换临时验证码后断开。
- 画面：
  - Windows 原生层逐行比较像素，画面内容没变就不重新编码，并用序号告诉 Dart 层「还是上一帧」；Dart 层据此不重复上传，只每 3 秒保活一次。此前无论画面是否变化，每 100 毫秒都上传一帧。
  - 只看系统的「有无新呈现」不够：被控端应用每得知一帧新画面就刷新界面，界面刷新又产生新的呈现，会让静止屏幕一直被当作变化。这是用发布候选构建验证时发现的，所以改为比较像素内容。
  - 采集轮询由 100 毫秒缩短到 50 毫秒。
  - JPEG 画质在 0.75 及以上时使用 4:4:4 色度，小号彩色文字不再发糊。
- 测试安全：被控端服务改为可注入，被控端测试使用记录型替身。此前自 2.3.6 加入的几个测试在 macOS 上运行时，会经真实服务在开发机屏幕上点击和拖动。

只发布 Windows。macOS 2.3.5（28）、Android 2.3.2（25）、iOS 商店 2.1.0 不变；开发机上的 Mac 为本地安装的 2.3.9，未公证、未发布。

## 未覆盖

- 没有测量真实链路上的帧率、延迟和带宽变化：上面的数字只说明重复帧不再发送，不代表流畅度提升了多少。经中继时的上传节流只由单元测试和时间戳推断。
- 采集分辨率上限仍是 1920。屏幕宽于 1920 的电脑，文字清晰度主要受缩小影响，本版没有改变。
- 中继观看者的名称：同账号免密连接是否会发出信任请求没有确认，若不会，提示条只显示「有设备正在访问此电脑」。
- 「断开所有远控」按钮只经组件测试，没有在真实会话中点击。
- 从 Mac 拖文件到 Windows 仍不可用：中继的文件下载接口只认观看端令牌，被控端取不到文件，各被控端也没有实现接收。
- 2.3.6–2.3.8 记录里的其他未覆盖项仍然有效。
