# RDesk 电脑与手机整体改版方案（已确认）

## 用户目标

修复真实 Windows 电脑上“无法读取网卡 / 未检测到有线网卡”，让 iPhone 能扫描 Windows 二维码完成开机配对。电脑和手机使用各自合适的界面，简洁、文字清楚、常用功能直接可达，参考 UU 的操作组织方式，保留 RDesk 品牌和实际能力边界。

用户已于 2026-09-20 确认本方案。本方案是设计与验收依据，目前尚未实施，也不是新版本已发布的说明。构建继续全部在本地完成，网站和发行文件部署到自有服务器。

## 本轮已确认的问题

1. 已实际打开 Mac 上的 UU，并通过它进入用户的 Windows。看见 RDesk 配置页同时出现“未找到已连接的有线网卡”和底部“无法读取网卡，请检查网线连接后重新检测”。这能确认查询失败被混同为没有网卡，不能确认网卡不存在，也不能推断 BIOS 不支持。
2. `WindowsWakeService.adapters()` 依赖 PowerShell、10 秒超时和 JSON 文本转换；页面捕获异常后丢失原因。PowerShell 固定 UTF-8 输出，但 app.dart 的 `Process.run` 使用默认系统编码。编码不一致、超时、脚本错误均应单独取证，尚未认定其中某一个就是这台电脑的根因。
3. 主导航有设备列表、云设备、远程连接、地址簿、我的五项，仅按宽度切换底栏/侧栏；桌面窄窗口仍可能变成手机导航。
4. 设置入口分散在“我的”、通用设置、连接设置、无人值守等页面；部分不适用于 Windows 的被控设置仍共享显示逻辑。
5. Windows 已有 PerMonitorV2 DPI 配置，不能把问题简单归因于没开启 DPI。主题缺少平台字体策略，部分辅助字仅 12–13，导航使用低透明度文字；需要在真实 Windows 本地显示下验收，远程画面压缩本身也会影响观感。
6. 当前没有二维码配对协议、扫码页面、扫码依赖及 iOS 相机用途声明。只画二维码不能完成配对。
7. 已连接 iPhone 17 Pro Max；iPhone 镜像目前被 Touch ID 锁住，尚未看到其 UU 页面。用户此前提供的 UU 手机截图可作为现阶段参考。

## 方案选择

- 推荐：保留 Flutter、现有账号和远控协议，拆分桌面/手机导航及平台功能展示；新增有实际服务端验证的扫码配对，重做 Windows 检测。改动集中在使用流程，可保留已可用功能与设备资料。
- 仅改颜色和字体：工作少，但设置层级、手机页面出现在电脑上及扫码缺失仍存在，不满足本次目标。
- 全部改成多套原生应用：平台贴合度高，但重复建设账号、远控、文件和发布流程，风险与范围明显增大，本轮不采用。

## 电脑端结构

固定桌面布局以操作系统判定；窗口变窄时侧栏收起为图标，不切换成手机底栏。保留账号资料，常用操作放在右侧主内容中。

```text
┌ RDesk ─────────────────────────────────────────────┐
│ 设备          │ 我的设备                 ＋添加设备 │
│ 远程协助      │ 全部 / 在线 / 收藏       搜索        │
│ 远程开机      │ ┌ 家中电脑 ──────────────────────┐  │
│               │ │ 助手在线 · 可发送开机信号  [开机]│  │
│               │ └──────────────────────────────┘  │
│               │ 其他已连接设备……                   │
│               │                                    │
│ 设置          │                                    │
│ 账号          │                                    │
└───────────────┴────────────────────────────────────┘
```

- 合并本地/云端设备展示，按稳定设备身份和服务器范围去重；收藏、地址簿以筛选和添加入口保留，不再占独立一级菜单。
- 远程协助页专注输入设备 ID 和连接，保留现有非账号直连能力。
- Windows 的“远程开机”页专注本机：网线/网卡检测结果、必要修复指引、展示配对二维码与到期时间。已配对后显示绑定状态和“重新配对”。不把手机端的长篇配置向导搬过来。
- Windows 尚不支持桌面被控，因此不展示本机屏幕共享、录屏权限、无障碍、无实际作用的无人值守被控控制。其他设备的开机操作仍可在设备卡片使用。
- macOS 使用同一桌面结构，但本机共享和权限按真实能力显示，不能把 Windows 的本机网卡配置套过去。

## 手机端结构与扫码

底栏收敛为“设备 / 协助 / 我的”。设备页右上角直接提供扫码入口，设备卡片提供开机或连接；不要要求先进入设置找到远程开机。

```text
设备                              [扫码] [＋]
全部     在线     收藏
┌ 家中 Windows 电脑 ──────────────────┐
│ 可发送开机信号 · 家中助手在线         │
│                         [开机]  [⋯] │
└─────────────────────────────────────┘

            设备       协助       我的
```

配对流程：

1. Windows 登录账号，执行本机检测，展示“用手机 RDesk 扫码添加这台电脑”。
2. iPhone / Android 打开设备页扫码，展示电脑名称和同账号校验结果，用户确认添加。
3. 手机选择留在家的 Android 助手；唯一在线助手可预选，多台需明确选。手机端承担局域网、BIOS 指引、实测流程。BIOS 仍由人在电脑上修改，手机只提供引导。
4. 设备页出现电脑卡片。后续用户在外用 iPhone 点开机；家中 Android 继续联网代发信号。
5. 未完成助手选择或 BIOS 核对时显示“待完成开机配置”，可继续，不显示已经可以开机。

扫码失败提供手动输入临时配对码；相机拒绝只影响扫码，不阻断设备列表与其他功能。iPhone 是控制端，不声称可替代 Android 在家长期后台发送开机信号。

## 设置扁平化与字体

- 桌面侧栏直接打开设置，内容采用“常规 / 安全 / 网络 / 关于”页内标签；“账号”直达账号资料。
- 手机“我的”直接显示少量常用开关与分组，详细项最多再进入一页。服务器地址等低频内容集中在网络，不在设备主页堆叠。
- 快捷入口：开机为设备卡片一次点击；扫码为设备页一次点击；桌面设置入口一次点击，具体项最多两次；取消重复的通用设置/连接设置入口。
- Windows 优先使用 Microsoft YaHei UI 与 Segoe UI 的系统字体组合，并配置中文回退；普通正文 15–16、辅助文字不低于 13、按钮至少 14，标题 22–24。主要文字使用实色，不依赖透明度削弱。
- 保持系统缩放和辅助功能文本缩放；验收 100%、125%、150%、200%，检查裁切、行高、图标与字体对齐。
- 白/浅灰底，蓝色仅用于主操作和选中态，减少渐变、装饰卡片和大圆角。成功、警告和失败必须同时有文字，不只靠颜色。

## Windows 检测与诊断方向

- 优先增加原生 Windows 网卡枚举桥接，读取接口类型、硬件标记、运行状态、名称与 MAC，避免把基础枚举依赖于 PowerShell 的本地化文本。
- 结合接口类型及硬件信息区分实际以太网、Wi-Fi、VPN、虚拟适配器；覆盖主板网口、USB 以太网和扩展坞。不能仅根据网卡名称判断，也不能把虚拟机通过当成物理电脑已验收。
- PowerShell 仅用于补充驱动唤醒能力查询，使用明确编码与进程超时/退出清理。查询失败不能抹掉已识别的物理网卡。
- 页面分别显示“检测中 / 检测失败 / 有线网卡未连接 / 未发现有线接口 / 已识别”，并提供复制诊断；诊断含来源、耗时、错误代码和脱敏适配器字段，不包含账号令牌或密码。
- 先采集用户真实电脑证据，再将可复现情况做回归用例；不能只扩大超时或增加一种枚举值后再次宣布问题解决。

## 配对协议与平台实现

- 新增与现有 wake API 并列的配对会话模块，复用账号认证。服务端短时保存待配对电脑信息，二维码仅含版本、随机会话标识和一次性高熵证明，不放账号口令、永久设备令牌或可直接执行的命令。
- 会话有效期 5 分钟，使用后原子消费，按账号绑定；过期、跨账号、重放、并发消费、被删除账号、旧服务器均明确报错。服务重启后未完成配对失效，桌面可生成新码。
- 手机只向当前已配置、已登录的 HTTPS 服务提交配对请求，不跟随二维码中任意服务器地址；不因扫码自动授予相机以外权限、修改账号或覆盖已有绑定。
- 电脑使用仅本次会话持有的独立证明领取自己的注册结果，服务端不把电脑长期心跳令牌返回给扫码端。完整入网后沿用当前专用心跳、助手令牌和开机回执协议。
- 手动配对码使用足够随机空间、同样短时失效及每账号/会话限速；不通过短码绕过账号一致性。
- iOS 增加真实相机扫码路径和用途声明，只在点击扫码后请求权限；Android 同样按需请求。保持 iOS 现有最低版本，避免为一个扫码入口无必要提高系统要求。
- 增加新增协议的本地 Rust 集成测试，覆盖配对与现有目标创建/解绑/删除的联动；先部署本地构建的兼容服务，再发新客户端。旧客户端保留原有非扫码配置路径。

## 验收与交付顺序

1. 诊断与网卡修复：在用户实际 Windows 复现并确认准确识别；保留虚拟机测试作为补充。退出应用后无遗留检测进程。
2. 桌面与手机导航、设置、字体：用真实窗口/手机检查常用操作路径，现有账号、历史、收藏和远控会话不丢失。
3. iPhone / Android 扫码配对：扫码成功、拒绝相机、错误二维码、过期、重放、跨账号、无在线助手、手机切后台、电脑重启等均有可解释结果。
4. 在已连接 iPhone 上本地安装测试版；测试 iPhone 发请求、Android 代发、Windows 上报上线的闭环。Android 助手当前未连接到本机，实际助手与硬件验收需保持独立记录。
5. 用户在场时安排睡眠、关机、蜂窝网络、隔夜测试，不自动让正在工作的 Windows 关机。
6. 本地构建 Windows / Android / macOS 安装包并更新自有官网下载。iOS 本地安装验证与 App Store 打包、上传、审核、正式可下载分别报告，不把官网发布当成 iOS 已更新。

保留工作区已有未提交的捕获与审核相关修改；新实现与这些文件相交时先核对差异，不能回退或直接混入发行成品。
