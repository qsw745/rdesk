# 远程开机：配置、排障与验收

补充实验路径（2026-09-21）：支持运行自定义程序的 Linux 路由器、NAS 或常开主机可使用[局域网助手与诊断工具](lan-wake-helper.md)，复用下述开机协议。尚未证明用户 AX3000T 原厂固件可以安装。App 中可选择安卓、Mac 助手；兼容 Linux 助手登记后同样出现在助手列表中。见[验证边界](validation/lan-wake-helper-2026-09-21.md)。

实现路径：手机或电脑上的 RDesk → HTTPS 账号服务 → 家中安卓前台助手 → 家庭局域网 UDP 广播 → Windows 有线网卡。无需公网 IP、端口映射或小米 AX3000 插件。此功能不提供 Windows 被控桌面。

## 首次配置（2026-09-28 起的简化流程）

电脑和手机登录同一账号即可，不再需要扫码配对、手机端配置向导或手动测试记录。

1. **家中助手**：在留在家里的安卓手机或 Mac 上登录，打开「远程开机」（手机在「我的」里，Mac 在左侧栏），开启「作为家中开机助手」。Mac 自动选择物理网卡（排除虚拟网桥、VPN 隧道等），只有多块物理网卡无法判断时才让用户选；macOS 13+ 可同时开启「登录 Mac 后自动打开 RDesk」。安卓建议在「后台设置」中允许后台运行、保持充电；助手不要求录屏或无障碍权限。
2. **Windows 电脑**：网线连接路由器，登录同一账号，在「远程开机」打开「允许远程开机」。确认对话框只列三个前提（网线与待机供电、BIOS 网络唤醒、家中常开助手）。开启时自动识别连接中的有线网卡，自动开启「登录 Windows 后自动启动 RDesk」，并自动选择家中助手（在线优先、最近活跃优先）直接登记目标；此时服务端即标记为配置完成。账号里还没有助手时，先在本机记住开启意图，任何助手上线后下次刷新自动完成登记。网卡唤醒相关驱动设置只读检测，未开启时提供「打开设备管理器」；BIOS 步骤收在可展开的说明里，程序不修改 BIOS、电源或网卡配置。
3. **发起开机**：在任意登录同一账号的设备上，设备列表和设备详情页对离线且已开启远程开机的电脑显示橙色「开机」按钮；「远程开机」页也列出所有可开机电脑。若电脑绑定的助手离线而账号里另有在线助手，发起开机时自动改用在线助手（服务端 `PUT /api/wake/targets/:id` 更换后再请求）；没有在线助手时直接提示原因，不发请求。多助手时可在电脑卡片「更多 → 更换家中助手」手动指定。

旧版本已经配对的 Windows 电脑不受影响：配对流程保存的上线凭据与现在的直接登记使用同一存储键，升级后心跳继续。服务端配对接口保留，只是客户端不再使用。

安卓助手以「Wi-Fi 网卡 + 唯一私有 IPv4 地址与前缀」识别家庭网络，不再把会每天轮换的 IPv6 临时地址、地址寿命和路由表算作网络变化。Wi-Fi 断开、路由器重启或切到其他网络时，助手暂停领取和发包、保留凭据，通知栏显示等待；回到同一 IPv4 家庭网段后自动继续，其他网络不会发送。停用保留助手身份和电脑绑定，再启用会轮换凭据；删除助手后，可在手机的电脑卡片「更多 → 更换家中助手」中重新绑定。普通同一接口的互联网短暂断线会退避重连。手机重启、系统强制结束后需重新打开应用启用；前台通知和充电也不能替代厂商后台限制与实机隔夜验证。

## 状态含义

| 状态 | 证据与处理 |
| --- | --- |
| 家中助手离线 | 30 秒内未收到该助手鉴权轮询；检查手机电源、Wi-Fi、通知与后台限制 |
| 请求已提交 / 助手正在发送 | 请求持久化或被该助手领取，不代表电脑已启动 |
| 信号已发送，等待电脑上线 | 安卓完成有界广播并回执；不会据此宣称开机成功 |
| 电脑已上线 | 请求创建后收到该 Windows 目标的专用心跳，且存在发送回执 |
| 未确认上线 | 120 秒观察结束未收到符合条件的心跳；检查 Windows 应用、网卡与主板 |
| 请求已过期 / 已取消 / 服务中断 | 本次不再发送；恢复环境后由用户重新发起 |

“当天可以、隔天失败”没有经过实机确认的根因。代码审查发现一个高度吻合的软件原因：2026-09-27 之前的安卓助手把整个链路属性（含 IPv6 临时地址及其标志、路由）当作网络身份，双栈宽带下这些值通常在一天内变化，助手会以 `network_changed` 自行停止并撤销凭据；Mac/Linux 助手在网卡短暂断开时也会直接退出。两者已改为暂停并在同一网段恢复，仍需隔夜实机复测确认。广播发送避免依赖路由器长期保存离线电脑的 ARP 项，但无法解决网卡待机掉电、主板不支持某种关机状态或安卓被系统停止等问题。

## 协议与安全边界

- 账号拥有目标与助手；各角色使用独立随机令牌，设备令牌不可调用账号管理接口。服务端仅存设备令牌 SHA-256 摘要，安卓使用 Keystore 加密，Windows 使用系统安全存储。
- 请求 30 秒有效；相同目标活动请求去重，每账号每分钟最多 10 个新请求。终态后仍遵守从创建时刻起 30 秒的冷却；每账号最多 20 台目标、5 个助手。
- 领取持久化后返回；发送前再授权，许可最多 2 秒且不得越过原有效期。安卓保守扣除授权往返耗时，发送 3 次、间隔 200 ms，仅在选定 Wi-Fi 的 IPv4 子网广播 UDP 9。
- 本地先记录请求 ID，再发送；重复领取只补回执。授权之后进程崩溃或回执丢失时不自动重发，可能显示不确定/过期，避免旧请求意外开机。
- 停止助手、退出账号、切换账号/服务器使本机待发操作失效。撤销到达服务端后阻止后续授权；已经发给助手的极短有效许可无法隔网原子撤回，已发出的 UDP 包也不能撤回。
- 最近在线时间在本服务运行期间保留最多 7 天用于诊断，在线判定仍只使用最近 30 秒。服务重启将所有非终态请求标为中断并清空在线租约和最近在线时间，不回放。配置与账号在同一用户文件原子保存；账号注销成功同步删除配置与记录，写入失败不先清内存账号。
- 诊断仅存状态、时间、错误码、配置关联，最多 7 天 / 每账号 50 条；没有原始令牌或 Magic Packet 内容。安卓额外保留最多 100 个请求 ID 与执行结果用于去重，不含 MAC 或凭据。

## 上线顺序

公网服务和 `/api/wake/` HTTPS 路由已于 2026-09-20 部署，通过协议测试，见 [部署记录](validation/remote-wake-deployment-2026-09-20.md)。客户端 2.1.2 简化配置流程；iOS App Store 版本更新另行处理。使用自建旧服务器时仍可能返回“服务器暂不支持远程开机”。服务端和客户端均在本地构建、验证后上传，不使用生产机或 GitHub Actions 构建。

服务仍使用既有 `rdesk-server` systemd 与用户文件路径。升级前备份用户文件；旧二进制不了解新增 wake 字段，直接降级后写文件可能丢失开机配置，回滚应恢复匹配备份。不要在不同版本服务进程间共享写入同一用户文件。
