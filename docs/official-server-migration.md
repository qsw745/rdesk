# 官方服务配置与迁移

2.3.12（35）起，普通版移除网络设置中的信令/中继地址编辑入口，也不从用户配置文件或旧偏好读取请求目标。官方来源集中在 `flutter_client/lib/src/utils/constants.dart` 的 `AppConstants.defaultSignalingServer`，中继使用同一来源；`OfficialServerConfig` 在运行时要求它是 HTTPS。局域网直连仍使用用户自己设备的地址。

## 同域名迁移服务器

服务器 IP 不是客户端配置。保留 `https://qisw.top`，先在新机器准备与旧版兼容的服务、用户数据、证书、反向代理和必要端口，在切换前验证鉴权、设备目录、帧上传/查看、输入、文件和开机助手协议。所有编译打包必须本地完成，只上传已验证成品。

安排迁移窗口，协调持久数据最终同步和会话停机，切换域名解析/入口转发，再从公网验证实际服务。DNS 缓存期间保留旧入口的兼容转发或维护响应，避免两边同时接收并分叉用户数据。保留旧成品及与之匹配的数据快照，确认稳定后再停用旧服务。仅切 DNS 不等于完成数据迁移；有状态会话可能需要重连。

## 必须更换官方域名时

修改集中配置并发布新客户端，证书与服务器身份验证保持开启。现有来源标记变化后，新客户端会清除旧账号会话、自动续登、生物识别登录及可信设备，要求用户在新服务重新登录；不把旧站凭据自动发送到新站。最早尚未绑定来源的历史账号，只允许迁入原官方来源 `https://qisw.top`。不得用 HTTP 重定向代替客户端迁移，账号 API 不跟随重定向。

## 老版本升级

- 已知历史官方配置：自动使用官方 HTTPS 地址并绑定账号来源，保留正常登录。
- 自定义服务器或来源不一致：先清除账号凭据和信任记录，再删除旧服务器偏好；界面需要重新登录。主题、永久访问密码和无关个人设置保留。
- 安全存储读取/删除失败：不写入完成标记、不发送账号请求，界面提示解锁设备后重试。
- 旧 `/settings?section=network` 深链回落常规设置；没有隐藏的普通用户服务器编辑框。

本次不引入私有部署模式、在线远程配置，也不声称实现了端到端加密。官方中继仍可解析转发内容；如需私有部署，应另行设计服务器身份和账号/信任隔离机制。
